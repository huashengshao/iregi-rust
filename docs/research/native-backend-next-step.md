# Native backend investigation: actual master request capture

The private shared binary-column candidate is numerically qualified and rejected on performance. Its durable evidence is in `validation/native-shared-binary/`: twelve native-versus-native timing groups give one improvement, two parity, seven regressions and two noisy intervals. Production remains unchanged. The next experiment captures real core requests before comparing the unchanged selected native kernels with Symbolica.

Existing whole-core evidence suggests inspecting backend selection before attempting another native emitter change. `validation/benchmark/native-4c32ece/results.json` and `baseline-4c32ece/results.json` cover the same revision, with all eight tensor/Laurent correctness comparisons passing. The native session achieved triangle singleton improvements relative to its own IREGI reference, but triangle batch32 remained slower. These are different host sessions; dividing their absolute medians would not establish a measured native-versus-Symbolica speedup. Both historical binaries remain available as `target/benchmark/kernel-{native,symbolica}-4c32ece`; their hashes were verified by the read-only review.

The current default `baseline-6b24c03-licensed/results.json` profile places N3 rank1 batch32 master work at about386.736µs, reduction at132.061µs, and instrumented total544.088µs, versus the independently measured reference333.156µs. Holding other work fixed leaves a diagnostic master budget near175.804µs, requiring roughly2.2× less master time. N2 rank1 batch32 has about117.292µs of profiled non-master work versus a97.462µs reference. Thus master optimization alone is unlikely to close every family. These are diagnostic estimates from separate profiling/reference measurements, not rigorous performance bounds.

`MasterEvaluator::new_with_backend` already selects native or Symbolica execution for a scalar family. Whole-core `PreparedExecution` currently chooses by the global `native-batch` feature; structural preparation is cached by Dual shape. A future per-family/backend policy must participate in cache identity and preserve the Symbolica Dual path. Simply enabling the native feature may instantiate the large D0 generated match arm, creating an unnecessary long compile for an N2/N3 experiment.

The bounded paired experiment uses the actual master request rows from the existing N2/N3 whole-reduction families. It reuses frozen optimized dependency archives and a private observational core hook. Normalization, validation, branch behavior, all six master outputs and all final tensor/Laurent outputs remain explicit. A raw-kernel comparison cannot qualify a backend policy for whole-reduction adoption.

The completed capture inserts one observational hook immediately after the public master call in `execution.rs`, retaining each group's family, input, request indices, public output and errors, then full statuses/tensor outputs. Ordinary A0/B0/C0 inputs have no numeric normalization or relabelling in this adapter; normalization applies to Dual and relabelling to D0. All captured rows are valid ordinary inputs. The coherent optimized closure is `target/benchmark/dependency-closures/6b24c03-complete-kinds`; the unchanged committed scalar dependency source was checked against the captured core revision `21622ec9abfdedcf18993768845a29a9bb1c1e1d`. The pre-existing uncommitted stability collector is explicitly excluded from the immutable source snapshot.

The durable `validation/native-master-replay/replay-qualification.json` and `decision.json` bind the unchanged binary, all four numerical snapshots, raw blocks, independent audit, and completed `20261023d` quiet window. External host activity was uncontrolled and is documented by the coordinator. No interval-dependent repeat or case omission occurred. The result supports a separately qualified whole-core experiment selecting these unchanged native families while retaining public validation and the Symbolica Dual path. The 19–30% batch master gain is smaller than the historical diagnostic triangle budget needed to close the IREGI gaps; these separate sessions cannot establish an end-to-end prediction. Production remains unchanged, and no IREGI parity claim follows from this raw-kernel result.

A possible later optimization uses existing Symbolica CSE. Oneloopmaster's direct builder uses `horner_iterations(0)`, which returns before the instruction CSE pass, although direct translation already reuses common Atom subexpressions within control-flow scope. The builder combination `horner_iterations(1).max_horner_scheme_variables(0).cpe_iterations(Some(0))` enables root CSE, but also applies an empty-variable Horner transformation to every registered function body, including unused D0 definitions. Shared helper bodies receive stack allocation, not the root's subsequent instruction CSE. Consequently, both preparation cost and the limited root scope need measurement before assuming a large C0 improvement.

Independent source review found an alternative existing public API: retain the exact six-output evaluator as `self`, construct an empty-output direct evaluator with the identical ordered parameters, then call `self.merge(empty, Some(0))`. Symbolica restores SSA, performs root CSE, skips common-pair elimination, and reallocates the stack. Empty incoming constants, instructions, results and helpers leave the original six results and shared definitions intact apart from root remapping. No additional `optimize_stack` call should follow. This avoids the whole-map Horner pass but still pays the existing one-time shared definition registration. In general, root CSE can sort Add/Mul operands and reuse identical power, builtin and pure external-function calls; operation-order equality cannot be assumed.

The bounded exact-only census in `validation/master-cse-census/` found no benefit from this route: A0 remains 43 instructions/6 temporary slots, B0 remains 506/13, and C0 remains 223/8. Operation counts also remain unchanged, and each exported root instruction listing is byte-identical before and after. All 18 output identities and 470 normalized control records pass the Symbolica exact-expression checks; C0's 41 helper bodies and registered constant descriptors remain unchanged. This identity proof assumes Symbolica's structured SSA, liveness and CSE dominance invariants and is not an independent runtime branch-definedness proof. The candidate stops here, without numerical or performance qualification. The completed Cargo debug artifacts linked this concrete Rational-only diagnostic in 5.58 seconds; exact construction and checking took 0.97 seconds. The initial missing compile-time `CARGO_CRATE_NAME` failure is retained. No dependency rebuild or production edit was needed.
