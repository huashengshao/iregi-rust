## 2. The 18 opening inputs

Source of truth: `validation/benchmark/opening-rank6-20261026/inputs.json` (sha256 `a0655111…a43a`, generated by
`make-inputs.py` there from `validation/highpoint-seven-point-current-cargo/fixture.json` sample 0). The binary64 campaign
copy `validation/benchmark/opening-double-20261026/inputs.json` (sha `5ff2278f…9659`, from its `make-inputs.py`) adds
precision/candidate fields only.

Kinematics ("E family"). Metric (+,−,−,−), time-first. Every value is an exact dyadic rational string and is exactly
representable in f64. Take the first N propagators of:

| i | shift p_i (t,x,y,z) | m_i² (re,im) |
|---|---|---|
| 1 | (0,0,0,0) | (1,0) |
| 2 | (0,1,0,0) | (2,0) |
| 3 | (0,0,1,0) | (3,0) |
| 4 | (0,0,0,1) | (4,0) |
| 5 | (1/2,0,0,0) | (2,0) |
| 6 | (0,1,1,0) | (3,0) |

Scale μ = 3 (the scale itself, not μ²). Denominators are (q+p_i)² − m_i² + i0, with powers ν_i and D = 4 + 2h − 2ε. The numerator is the
4-dimensional Cartesian monomial q^α. Every call requests **all cumulative moments |α| ≤ R** (count C(R+4,4)) × 4 Laurent slots.
Dots always sit on the **first** propagator.

requested_bits b means the TIRust internal admission target is 2^(19−b): 53 → 2^-34, and 39 → 2^-20 ≈ 9.5e-7. COLLIER requests 1e-6 for
the high three rows and 1e-10 for the others. COLLIER can only take the 12 ordinary rows, because its public tensor API has no powers or dimension-shift input.

Per-case JSON (`cases[i].driver_request`) holds `id, n, rank, powers, dimension_shift, algorithm, numeric_type, working_bits,
requested_bits, samples:[{shifts:[[t,x,y,z] strings], masses_squared:[[re,im] strings], mu:"3"}], warmup, repeats,
iterations, target_block_ns, maximum_iterations`. The opening-double copy adds `candidates:[{id, request}]`, which adds
`master_policy` ("NativeF64Abc" | "Symbolica") and `postconstruction_profiling`.

TIRust packs this into `KinematicsBatch{rows, components:1, values}` with **5N+1 complex values per row**, in this order: 4N shift
components (row-major p_1(t,x,y,z), p_2…, imag 0), then N complex m², then μ (imag 0)
(`crates/iregi-rust/examples/opening_double.rs:171-198`; the same layout is in `kernel_benchmark.rs`).

## 3. Reference arrays: location, format, ordering, normalization

**Primary reference used by every opening comparison:** `validation/benchmark/opening-rank6-20261026/cases/<id>/result.json` →
`first_output` (`final_output` is identical). This is the previous TIRust output, independently admitted against original-IREGI
**quad** IBP arrays in all 8,968 complex fields at a mixed 1e-10 tolerance (max 2.714e-13). See `reference-comparison.json`
(sha `5d72855e…`), produced by `compare-reference.py`.
- `first_output.basis`: list of [t,x,y,z] exponents. Order: rank blocks ascending; inside a block the t exponent descends, then x,
  then y, and z is the remainder. Rank 2 is `00,01,02,03,11,12,13,22,23,33` (`compare-reference.py::basis`, and the
  `degrees()` helpers in `run.py:197` and `collier/run.py:133`). This matches IREGI's native order with `ML5_CONVENTION=.true.`
  (unweighted raw monomials, no multinomial weights) and COLLIER's (nt,nx,ny,nz) loop.
- `first_output.laurent_order = ["UV single","IR single","IR double","finite"]` (IREGI's `uv1, ir1, ir2, finite`).
- `first_output.lanes[0].values`: flat list of length 4·M. **Index = 4·moment + slot.** Each entry is `[re, im]`, and each part is
  `{"exact_rational": "p/q", "finite": bool, "negative_sign": bool, "working_bits": int}`. Decode with `Fraction(exact_rational)`.
- `convention: "IregiNative"`, `tensor_weights: "Components"`, `components: 1`. Status `Success`.
- Precision of the references: ordinary N1-N4 are f64 TIRust Hybrid outputs (53 bits, agreeing with quad IREGI to ≤ 1e-13 mixed).
  N5/N6 ordinary and all six extended rows are Symbolica `Float` 128-bit (Hybrid / Ibp) outputs. Many fields are exactly zero:
  IR slots are 0 on this IR-finite family, plus symmetry zeros. For example, N3R2 has 48 of 60 fields with both parts zero.
- Original quad-IREGI raw arrays (decimal text, `poles` uv1/ir1/ir2/finite) live in hash-pinned capsules
  `validation/quad-original-iregi-{small-n-rank7,generalized-rank7,positive-rank-anchors,rank7-adjudication,low-n-rank6-dot-triple}/payload.tar.gz`.
  The per-row mapping is in `opening-rank6-20261026/independent-timing-boundary-and-fixture-review.json` → `fixture_rows[*].reference_*`.
  `compare-reference.py` extracts them. They are not needed for E/A.

**Native IREGI normalization vs COLLIER** (COLLIER driver `collier/driver.f90:39-40, 396-416`, with μ_UV² = μ_IR² = μ² and Δ_UV = Δ_IR = 0):
`slot UV = iπ²·T_uv`, `IR1 = IR2 = 0`, `finite = iπ²·(T − (γ_E + ln π)·T_uv)`. Here T and T_uv are COLLIER's tensor and UV-coefficient
arrays for Aten/Bten/Cten/Dten/TNten. A scaleless bubble in native IREGI has UV +iπ² and IR1 −iπ² (`validation/reference/README.md`).

## 4. Accuracy metric E/A (documented "array-relative error")

From `opening-double-20261026/run.py:152-189` (`accuracy()`) and `collier/run.py:157-199` (`inspect_array()`):

- weight `w_j = μ^(d_j + 4 + 2h − 2·Σν_i)`, where d_j = Σα of moment j (COLLIER uses d+4−2N, which is the same for ordinary rows)
- `E = max_j |x_j − x_j^ref| / w_j` and `A = max_j |x_j^ref| / w_j`, with j running over **all moments × all 4 Laurent slots**
  (complex modulus)
- `δ_rel = E/A` (if A = 0, the result is 0 when E = 0 and undefined otherwise). The computation is done in exact `Fraction`s on the represented binary values, as squared quantities, with a sqrt at the end.
- Also retained: the mixed metric `max_j |x−x^ref|² / max(w_j², |x^ref|²)` (sqrt is reported), and booleans `≤1e-6`, `≤1e-3`.
- The old 1e-10 gate in `compare-reference.py` uses `natural_scale_squared = max(1, μ², |m²|, |s_ij|) = 9`, which for this family is the same as μ² = 9.
- Selection policy ("optimistic"): fastest mean among candidates that give a complete finite array with E/A ≤ 1e-3. If none qualifies,
  the fastest diagnostic is shown amber with "Refused output · diagnostic timing" and "accuracy unavailable". Refused lanes stay `null` and are
  never zero-filled. Nonfinite fields are counted, and any finite-subset error is diagnostic only.
- Ready-made helper: `$S/smoke_iregi.py::ea(case, moments)`, where `moments[m][slot] = [re, im]` (floats or strings). It reads the
  reference from the path above and returns E/A as a float.

## 6. Original IREGI: limits, build and run

Original sources: `/shared/external/iregi/references/madgraph/vendor/IREGI/src` (read-only). Reference build (already present):
`bash scripts/build-reference.sh` → `validation/reference/build.py`. Its outputs are `target/reference/{objects/*.o,*.mod, patched/funlib.{f90,o},
iregi-reference, iregi-reference-original, provenance.json}`. Flags are `-O3 -fPIC -std=legacy -fallow-argument-mismatch`, gfortran 15.2.0.
The only patch is the factorial_pair table (`validation/reference/factorial_pair.patch`), which is needed by `general_ti_reduce`.

**Limits** (`global.f90:6` `MAXRANK_IREGI=7, MAXNLOOP_IREGI=7, MAXINDICES_IREGI=10`; `ti_reduce.f90:118-123`,
`gti_reduce.f90:79-98`):
- n_eff = N − #(propagators with |p_i| < 1e-10) must be **< 7**. With zero-origin routing that means N ≤ 7. Rank ≤ 7.
- Powers 1..10. The dimension shift `idim = d−4+2ε` must be **even** (`idim = 2h`); odd values hit `STOP`. Powers ≠ 1 or idim ≠ 0 require
  `general_ti_reduce`, which needs real masses and **a zero first shift**. The ordinary `tensor_integral_reduce` requires unit powers and h = 0.
- Modes 0 = IBP, 1 = PV, 2 = Hybrid (PV → IBP). The general API uses PV coefficients for any nonzero mode.
- Failure modes: Fortran `STOP` exits with **code 0 and no RESULT** (for example PV/Hybrid on N2R6: "ERROR:out of range of pave_UV").
  So **use one process per (input, mode)** and treat a missing RESULT as failure. `stable=false` means the lane cannot be used.

**Existing timing driver** `validation/benchmark/driver.f90` → `target/benchmark/iregi-benchmark`, built by
`validation/benchmark/build_reference.py`. Careful: that script *overwrites* `target/benchmark/iregi-benchmark` and `reference-build.json`, so
build new copies elsewhere. Link command:
```bash
R=target/reference; OBJS=$(ls $R/objects/*.o | grep -v -E '/(driver|factorial_table|funlib)\.o$')
gfortran -O3 -std=legacy -fallow-argument-mismatch -J OUTDIR -I $R/objects DRIVER.f90 $OBJS $R/patched/funlib.o -o OUTDIR/BIN
```
Wire protocol (stdin; banner then `READY IREGI_BENCHMARK_V1`):
```
BENCH id mode n rank mu batch warmup repeats iterations        (batch ≤ 4096, one common mu per batch)
p0 p1 p2 p3 (m2re,m2im)                                         (n rows per lane, lane-major)
...
QUIT
```
→ `RESULT {"id","stable","clock_ticks_per_second","total_ns":[per-call mean of each repeat block],"lanes":[{"status":"success"|"unstable","moments":[[[re,im]×4] × C(R+4,4)]}]}`.
Each repeat block times `iterations` complete batches. Per lane this covers mass-reference setup, `tensor_integral_reduce` (or `comp_…` for complex masses),
a finiteness check and `IREGI_FREE_PS`. `INITIREGI(.true.,2,1d-12)`, `ONSHELL_IREGI=.false.`, `ML5_CONVENTION=.true.` and `MU_R_IREGI=mu`
are set per request, outside the timer. Output moments are the final evaluation's array, in the same order and slots as the reference.

**Generalized timing driver (new, scratch prototype)**: `$S/driver_general.f90`, built as `$S/iregi-benchmark-general` with the command above.
Its header is `BENCH id api mode n rank idim mu batch warmup repeats iterations`, where `api` is `tensor`|`general` and `idim = 2h`. Rows are
`p0 p1 p2 p3 (m2re,m2im) power`. The output format is the same. It was verified on all 6 extended rows plus N3R2 (general and tensor give the same E/A).

Smoke and prelim runner scripts: `$S/smoke_iregi.py`, `$S/smoke_iregi_general.py`, `$S/prelim_iregi_collier.py`.

COLLIER wire: `BENCH|CHECK id mode n rank mu batch warmup repeats iterations reqacc critacc tenred argperm` followed by the n rows
`p0 p1 p2 p3 (m2re,m2im)`. It requires a zero first shift, positive real masses, and the bound min m² − max(s_ij⁺)/2 > 0. The archived driver enforces `batch == 1`
(`driver.f90:63`). For batch-32, use the one-line variant `$S/collier_driver_batch.f90` (`batch<1.or.batch>4096`), which I linked and smoke-tested at batch 4:
```bash
C=target/reference/collier/build-attempt001/source
gfortran -O3 -std=legacy -fallow-argument-mismatch -Wtabs -J OUTDIR -I $C/modules DRIVER.f90 $C/libcollier.a -o OUTDIR/collier-batch
```
Inside a batch, COLLIER loops over lanes and calls the scalar API per lane, so batch throughput is the sum of the scalar calls.

- The opening-double `collier/run.py request()` rejects non-ordinary rows and `len(samples)!=1`.
- The IREGI benchmark driver does not dedupe mass references the way `validation/reference/driver.f90` does. Results still agree (E/A ≤ 4e-11).
- The IREGI driver writes a OneLOop banner before `READY…`. Parse only `RESULT ` lines.
- `validation/benchmark/build_reference.py` and `build.py` write fixed paths (`target/benchmark/iregi-benchmark`, `target/optimized`);
  don't clobber them. Point new builds at `target/fast-engine-<date>/`.
- The old TIRust per-call `Instant` timing at sub-µs scale (N1R0 0.97 µs) includes timer overhead. Prefer block timing.
- `opening_double.rs` validates `requested_bits ∈ [20, 53]` and `n ≤ 6`, `rank ≤ 6`. Keep the same domain checks.
- The COLLIER N6R6 output is nonfinite in every public configuration: a diagnostic time only, amber.
