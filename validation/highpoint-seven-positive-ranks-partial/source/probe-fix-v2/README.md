# Narrow private probe continuation

The first actual Cargo build remains failed and immutable: Rust E0616 rejected
the validation probe's access to private `BatchResult.values`. The independently
reviewed correction removes only that expression. Successful `result.lane()`
width checks, all other layout guards and every reduction/master source remain.
The old probe source, failed receipt/log, successful partial core/master events,
exact artifact hashes and separate preserved copies remain bound by lineage.

This continuation adds no source/dependency closure or cache copy. `prepare.py`
only seals small source/metadata bytes and verifies the exact one-line deletion.
It does not hash libraries, invoke Cargo or evaluate an integral. No helper here
has been run merely by its creation. The new protocol needs its own independent
`source-review.json` and exact ROOT grants under `grants/` before producer use.

`run.py` is the frozen reviewed controller with only its explicit helper import
and build-attempt number changed. `continuation.py` supplies the new context and
output paths while reusing the original common primitives, original Cargo
metadata and command, c193 lifecycle, shape checks and saved math module.
There is no monkeypatch of the original module or modification to its protocol.

At each runtime boundary the existing31,250-entry lineage map is reconstructed
and exactly the probe source digest is rebound from the preserved old snapshot
to its corrected digest. The rest of that map stays unchanged. Full pre/post
byte guards run once per aggregate under the original absolute deadline.
Before build, the preserved artifact membership is checked; the successful
new probe then legitimately adds its files and the produced closure guards
that new membership. Original source maps remain historical evidence.

Core and masters may be Cargo `fresh:true` only if every field of their emitted
events except that flag matches the actual `fresh:false` partial-build events,
and every emitted rlib/rmeta byte hash matches its preserved counterpart.
The corrected probe must be `fresh:false` with exact private package/source IDs.
Historical public/private executables cannot substitute for the new probe.

Operations are `build`, `capture128`, `capture256`, `compare`. Output paths are
`runs/build-002`, `runs/capture128-001`, `runs/capture256-001`, `runs/compare-001`
under this directory. Budgets stay900/120/720 on CPUs20–21 for the warm build,
900/120/600 and1200/150/960 on CPU6 for the rank1 captures, and120/15/no-child
for saved comparison. No preparation-only run, cache replay or cold dependency
rebuild is requested. Failed attempts are retained without automatic retry.

the exact unchanged policy fields, new protocol/review hashes, prerequisite

bc97b82e… independent lineage review. Build also needs the isolated-cache owner
