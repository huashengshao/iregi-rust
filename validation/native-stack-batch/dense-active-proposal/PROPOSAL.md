# Read-only proposal: contiguous active spans

The present evidence supports testing a dense-span loop path in the existing oneloopmaster emitter. It does not establish that indexed loops dominate runtime, or that this change will improve performance. No emitter, arithmetic primitive, production kernel or additional candidate binary has been changed for this proposal.

## Existing facilities and compiler evidence

- `dependencies/oneloopmaster/src/rust_codegen/batch.rs:58` chooses one global `controlled = has_control_flow(graph)` flag. This recursively includes all helpers. At line176, controlled functions use `for &lane in &active[..active_len]`; otherwise they already use `for lane in 0..rows`. Consequently even a straight-line helper receives indexed loops when any graph branches.
- `dependencies/oneloopmaster/src/native/batch.rs:176` already provides checked SoA storage and parent stride, root lanes in ascending order, and active/resume storage. `copy_column` at line238 uses split, disjoint column slices and a contiguous zip. `copy_active_column` at line265 retains an arbitrary index-list fallback. No contiguous-active-span abstraction was found in this emitter/runtime. An independent source audit also found Symbolica's batch evaluator retaining its active Vec at each instruction.
- The retained qualified C0 f64 binary, built with opt3/codegen16 and no explicit target-cpu flag, contains the loops in `c0-baseline-helper1.asm`. The Mul loop at 0x1d54a0 loads one active index, checks both source addresses and the target address, computes one complex product and advances the index pointer by8 bytes. The Add loop at 0x1d5540 similarly loads one active index and checks its source/target addresses. Its `addpd` operates on that complex value's real/imaginary pair, not multiple consecutive sample positions. Thus packed SSE in this assembly is not evidence of batching across adjacent samples. Broader SIMD or bounds-check elimination is a hypothesis for a small compiler experiment, not a measured benefit.

## Smallest useful candidate

Keep the existing active array and sparse path. At function entry and after IfElse, Label and Goto transitions, classify the active sequence as empty, one contiguous span or sparse. Root lanes are0..rows; stable filtering preserves order and uniqueness; Label reconstructs from the sorted caller lanes; helper calls receive the parent's sorted subsequence. Therefore a nonempty span is recognizable from its endpoints and length without another scan. Use checked endpoint arithmetic and keep the retained parent stride, which may exceed current rows after workspace reuse.

Emit a contiguous range loop only for Add/Mul when that metadata says the active list is one span. Reuse the same existing primitive calls and exact exported operand order. Keep the current indexed loop for arbitrary subsets. Initially avoid a list of multiple runs: it adds metadata and inner-loop dispatch to mixed branches. Evaluate whether existing `copy_column` can separately serve dense copies by shifting the arena view to the span start; its target/source alias no-op and disjoint slicing are already implemented. Copy optimization is a separate experimental variable from Add/Mul.

The first proof should use the existing baseline native root graph, independently of the rejected root-slot allocation candidate. Start with a small existing exported helper containing Add/Mul and branches, then C0 f64 only if compiler evidence warrants it. Do not regenerate or compile another all-domain D0 merely to test this idea. D0 source outlining already makes code size/compilation material; duplicating every whole body into dense/sparse versions could increase instruction-cache pressure and compile cost.

## Required invariants and qualification

Finish every source read for a lane before replacing the destination. The observed helper's Add already aliases a source slot with its destination; deriving simultaneous mutable destination and immutable aliased source slices is invalid. Preserve the current expression-then-assignment form unless a separate safe alias classification is proved. Preserve instruction-major ordering, ascending lane order, all helper and branch labels, lazy Join arms, signed zeros, precision and the exact arithmetic primitives for f64/DoubleFloat/Float. No reassociation, replacement algebra, FMA changes or new constants belong in this loop experiment.

Exercise empty and singleton batches, span starts above0, retained stride, odd tails, alternating sparse lanes, all/none branch predicates, reactivation at Labels, inherited helper subsets, repeated destination/source slots and reused Out slots. Check all six outputs against the current native path with exact represented-value/precision/signed-zero comparison; existing interpreter differences remain a separate field. Then use before/after-qualified fixed-loop timings for homogeneous, grouped and interleaved rows. Require every relevant batch/singleton family to pass the existing confidence gate before adoption. A source/assembly improvement alone is insufficient.
