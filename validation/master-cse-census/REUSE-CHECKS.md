# Existing algebra and export facilities

This exact-only diagnostic uses existing Symbolica `ExpressionEvaluator::merge(empty, Some(0))` for optimization. It adds no simplifier, polynomial algorithm, recurrence, or control-flow algebra.

Three reuse checks were completed before selecting the small validation adapter:

1. **Symbolica APIs and source.** Searched `dependencies/symbolica/src/evaluate/` for evaluator-to-Atom, expression, tree and reverse-export methods. `ExpressionEvaluator::export_instructions` is the available portable IR export. `AtomView::to_evaluation_tree` and `to_eval_tree_multiple` construct evaluator trees from original Atoms; they do not reconstruct transformed instruction programs. Existing C++/SIMD/CUDA exports generate numerical code. No public inverse exporter from transformed evaluator instructions to Atom was found. Root CSE, stack restoration and branch dominance remain Symbolica's implementation.
2. **Existing usage and tests.** Inspected Symbolica evaluator/CSE/branch/alias tests and existing project proof adapters in `target/cli-coefficient-optimization/source/proof.rs` and `target/stack-reuse-production/factory_probe.rs`. The former reconstructs exact expressions solely through Atom arithmetic and proves differences with Symbolica expansion. The latter records allocated-slot provenance with complete RHS reads before overwriting destinations. Both precedents inform this diagnostic. Symbolica's own `undo_stack_optimization` uses the same linear storage-version restoration on its generated structured IR.
3. **FeynKit/gammaloop/Spenso equivalents.** Searched their Rust sources for exported instruction reconstruction and evaluator-to-expression APIs. Spenso `network/symbolica_interop.rs::to_expression_at` reconstructs tensor-network contraction trees through a supplied callback, not Symbolica evaluator instructions. Network parsing/materialization helpers similarly target tensor graphs. No reusable inverse scalar evaluator exporter was found.

The adapter only maps exported primitive operations to Symbolica Atoms, retains opaque calls identified by exact symbol and ordered tags, and retains registered constant descriptors instead of rational placeholders. All arithmetic, canonicalization and zero proofs use Symbolica. It checks the six output expressions and normalized control labels/conditions, and compares all recursive helper bodies and constant metadata unchanged.

The resulting exact-expression certificate **assumes Symbolica's generated structured SSA, liveness and CSE dominance invariants**. Sequential reconstruction is not an independent proof of lazy branch definedness: incorrect use of a branch-local value could reconstruct the expected expression while failing on another runtime path. No numerical, inactive-domain, signed-zero, mixed-precision, Dual or performance qualification follows from this census. Those remain separate work before any adoption.
