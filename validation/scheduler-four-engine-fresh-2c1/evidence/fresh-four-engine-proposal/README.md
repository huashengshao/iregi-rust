# Fresh four-engine preflight/timing proposal

This folder supplies concrete preparation, runner, admission and analyzer
sources. No preparer, probe, compiler, numerical integral or timing cohort has
been launched. Actual build/qualification/preflight receipts, independent
admissions, immutable CPU grants and executable hashes remain mandatory deferred
inputs. This is a private pinned2c1f334 source experiment using the frozen optimized
lower dependency context; it does not qualify later production source or native
master policy.

The measured engines are baselineTIRust and candidateTIRust (both generic
Symbolica masters), original IREGI Hybrid2 and COLLIER1.2.10 COLI mode1.
Two separately compiled captured companions run outside measured intervals,
so there are six owned processes and four timed engines. `interactive.py` copies
the retained transport with only an explicit CPU argument; there is no CPU32
literal in process launch. `lifecycle.py` is byte-identical to the reviewed
whole-process-group helper. Every child uses the same granted single CPU.

## Prerequisites and deferred preparation

Both fresh captured and capture-free60-request qualifications must finish,
retain120 events each and receive independent complete saved-data admission.
The capture-free gate must preserve52 exact same-phase projections and direct
six-output controls. Minimal linked admission contracts are in the source-only
protocol template; they require real hashes, full fresh independent review links
and pinned revision2c1f334. Historical opt0 or selected-native reviews do not
satisfy these gates. The coherent14-product compiler/provenance admission must
also pass and bind all six relevant executable paths and archive identities.

## Preflight, preparation order and correctness

Each of the four TIRust processes receives all eight CASEs in frozen input order,
each immediately repeated before it sees CONTROLS:64 total initialization
responses. This matches each process's own CASE-first qualification history.
Initial and repeated complete replies must match the corresponding fresh saved
snapshots, including `plan_reused`. Then all four CONTROLS replies must match
fresh own snapshots and exact captured/capture-free projections.

Before and after every family, collect six full responses: two captured CASEs,
two capture-free CASEs, IREGI, and COLLIER CHECK. Every tensor/Laurent coefficient
and successful status is validated. Captured observations retain all six master
outputs, exact represented values/precision/sign, requests/routing, errors,
branch/backend and counters. Captured/capture-free current-phase projections keep
`plan_reused` exact; only capture arrays and explicit root mode fields differ.
Comparisons to fresh own snapshots permit only the documented workspace reuse
metadata difference when a family is revisited. Direct master controls remain
fully intact. COLLIER independently varied UV/IRsingle/IRdouble pole probes must
be finite, nonnegative and<=1e-12 and satisfy its existing UV identities.

Cross-engine comparison uses the unchanged1e-10 dimensionally normalized full
complex criterion from the frozen helper. Native normalization, pole ordering,
routing and scalar masters are unchanged. The report scope is precisely eight
massive Euclidean N2/N3 rank0/1 families at batch1/32, with common scale.
This does not qualify more topologies, higher rank, physical performance or Dual
performance. Preflight sends no calibration or timed acceptance requests.

## Fixed timing protocol

A timing protocol requires a passed independently reviewed preflight of these
same sources, qualifications and CPU. It additionally requires a new immutable
root-owned CPU quiet grant. Add `--preflight-independent-admission`, its SHA,
`--quiet-grant` and its SHA to the preparation command. Contracts in the template
bind the exact unique run ID and absolute attempt directory, one_shot=true, a
nonempty root coordinator authorization declaration, CPU, SMT siblings, source
manifest, six process labels, fixed budget and exclusive project compiler/numerical
lease. Preparation, execution and analysis check this same one-shot binding.
The runner refuses an existing attempt directory. Full generated protocol SHA
review follows binding the actual grant bytes, avoiding grant/protocol hash
circularity. The caller must arrange exclusion;
this code does not kill unrelated work or infer a grant from low utilization.

Every family keeps48 quartets: all24 four-engine permutations twice, shuffled
once with Random(173); the same balanced order list is used per family. All
engines share a positive signed32 count. Calibration starts at1, warms each
engine10 times only on round0, and has at most8 rounds. If the fastest block is
below100ms, n=max(n+1,ceil(n*110ms/min_elapsed)). Count overflow is rejected.
Acceptance starts only after all four calibration intervals reach100ms and keeps
n fixed for all48 quartets, warmup0. No retry, recalibration, CI-based extension
or sample replacement is allowed. A remaining-budget check can leave explicit
budget-inconclusive and unrun families; it cannot increase the bound.

The existing Rust probe measures complete public reduce_batch calls with one
Instant pair per fixed-count block, black_box inputs/results, every-call success
checks and owned result drop inside the interval. Capture/profiling are absent
from timed cores. Parsing, transport, preparation and captured companion work
stay outside kernel intervals. Fortran drivers return floating ns/call, so their
block duration is explicitly reconstructed as ns/call*n rather than called raw
integer ticks. Every timed response must match its own complete untimed arrays.

## Raw accounting, terminal policy and statistics

The runner preserves every request/response payload, wrapped reply and serial,
stdout/stderr, process group, terminal state, source/artifact binding and deadline.
The analyzer independently checks exact stage order, initialization, controls,
before/after families, calibration arithmetic, signed32 shared counts, balanced
quartets and all raw durations. Every raw event is accounted exactly once.
Terminal/owned-group cleanup precedes post-execution hashes. The analyzer also
requires exact six-label stdout/stderr hash inventories and directly rehashes
all twelve persisted log files; missing, extra or changed logs fail admission.

Global lifecycle admission is separate from row-local short intervals. All six
exits0/groups gone, numeric/control checks, exact guards, complete eight-family
corpus, raw accounting and fixed deadline are required. A raw-derived acceptance
interval below100ms marks all five ratios of that family inconclusive while
leaving other complete families eligible. It cannot excuse any global numeric,
process, source, raw or deadline failure. Incomplete/failed/unrun families remain
visible and disqualify complete-cohort speed admission.

All five ratios have TIRust in their numerator:

- baselineTIRust / IREGI;
- candidateTIRust / IREGI;
- baselineTIRust / COLLIER;
- candidateTIRust / COLLIER;
- candidateTIRust / baselineTIRust.

Statistics reuse the exact frozen median bootstrap helper:10000 seeded173
resamples,99% linear quantile interval0.005/0.995, relative width<=2%. Narrow
high<1 is improvement, low<=1<=high parity, low>1 regression; otherwise noise is
inconclusive. Preserve48 paired values,24/24 order strata and slower-pair counts.
Never pool sessions or multiply ratios from historical cohorts.

A timing analysis requires a separate root quiet-release file linked to its
terminal receipt and immutable grant. Only after cleanup, guards and release:

```sh
python3 /absolute/path/to/fresh-four-engine-proposal/analyze.py /absolute/path/to/attempt \
  --quiet-release /absolute/path/to/release.json --quiet-release-sha256 ACTUAL_SHA
```

Preflight analysis takes only its attempt path. It reports no timing ratios and
still requires a later independent complete saved-data review. No source-only
check, preflight, private candidate result or report update constitutes production
adoption or a performance-parity claim.
