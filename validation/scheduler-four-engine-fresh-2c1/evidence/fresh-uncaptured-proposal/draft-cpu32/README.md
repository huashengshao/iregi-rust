# Fresh capture-free60-request qualification and captured projection

This folder contains source-only tooling. No executable, compiler, numerical
integral or timing run has been launched. Actual executable/build/captured receipt
hashes in `protocol-template.json` are deliberately deferred until successful
build and captured numerical admission. This gate alone cannot authorize timing
or apply the scheduler candidate to production.

The target cohort uses pinned source revision
`2c1f3342e189a20fef3bbf7dd9e0baa372e2b4a2` with the same frozen optimized lower
dependency context as its captured companion cohort. A historical captured review
does not qualify new opt3 products.

## Preserved corpus and narrow deltas

`run.py` inherits the established60-request/120-event bounded lifecycle and the
eight N2/N3 rank0/1 batch1/32 massive Euclidean families. Each process receives30
responses: eight initial CASEs, eight own repeats, eight retained-workspace CASEs,
two CONTROLS, and four explicit invalid-request controls. Every successful tensor,
Laurent/Taylor component, exact rational, precision, sign, lane status, fallback,
diagnostic, counter and direct all-six scalar-master output remains checked.

`interactive.py`, `lifecycle.py`, `control-shapes.json`, and
`captured_admission.py` are byte-identical copies of their recorded origins.
`admission.py.patch` changes only the whole-core observation capture validator
(to require exactly[] and return zero capture counts) and normal-response root
scope/capture_enabled fields. Direct scalar master snapshots, failed-lane/null
checks, derivative controls and all-six outputs are unchanged. The captured gate
retains its complete master observations; none of its data is overwritten.

`run.py.patch` adds saved-anchor projection, this folder's HERE path, mode-specific
invalid-request expectations and projection completion fields. The fixed300s
aggregate,20s cleanup/postguard reserve, CPU32, first-failure policy, owned group
cleanup, terminal-before-posthash order and60-request inventory remain intact.
This source template is not a fresh numerical resource grant. The copied session
transport intentionally uses CPU32; later quiet-window timing requires its own
reviewed CPU adapter.

## Exact projection onto separately admitted captured responses

`projection.py` validates a real captured results receipt and its120 raw request/
response events. It binds the exact serial/stage/key/engine/payload signature of
all52 normal responses (CASEs and CONTROLS). Captured own repeats, retained
workspaces, cross-scheduler equality and full control schemas are rechecked.
The captured receipt must also have a separately passed independent saved-data
review; `prepare.py` enforces that linkage before creating an actual protocol.

For each normal uncaptured reply, its capture-free full schema is validated,
then compared exactly with the same captured phase. Projection removes only:

- `master_captures` keys recursively;
- the normal envelope's root `result.scope`;
- the normal envelope's root `result.capture_enabled`.

Every other field remains, including `plan_reused`. Root modes are validated
separately before projection. Direct master controls have no `master_captures`
field and remain fully intact. This is not a numerical tolerance comparison and
does not substitute projected empty arrays for independently retained master
results. All original wrapped responses and request payloads remain in raw data.

## Invalid-request controls without measured work

The four requests are sent to both processes after the52 normal responses:

1. `engine="baseline"` with default iterations=0 and repeats=0 reaches the
   wrapper/core timing guard and returns wrapped `result.error`, exactly
   `timing requires own variant and one positive signed32 fixed-count block`.
   For the candidate process the own selector is also invalid. In both cases
   the guard is before the Instant measurement and iteration loop.
2. `warmup=1` with no engine returns `invalid_request`.
3. `repeats=1` with no engine returns `invalid_request`.
4. `iterations=1` with no engine returns `invalid_request`.

The last three errors must say `untimed request must not carry timing counts`.
The probe can construct/reuse its structural plan before the first guard; this
control is not described as a no-code-path-entry test. No positive measured
block is requested or executed by this qualification protocol. These eight
expected replies deliberately differ from captured dispatch rejection and are
validated directly rather than projected.

## Deferred preparation contract

After the terminal14-product build/provenance admission and successful captured
qualification, obtain an independent review of the actual fresh captured120
events. Supply a small explicit admission JSON, linked to that full review:

```json
{
  "status": "passed",
  "receipt_sha256": "<actual fresh captured results.json SHA256>",
  "raw_sha256": "<actual fresh captured responses.jsonl SHA256>",
  "request_count": 60,
  "raw_event_count": 120,
  "all_complete_records_and_controls_checked": true,
  "full_review_path": "<absolute path to the actual fresh independent full review>",
  "full_review_sha256": "<actual full review SHA256>",
  "pinned_source_revision": "2c1f3342e189a20fef3bbf7dd9e0baa372e2b4a2"
}
```

The admission may be a compact reviewer receipt or a separate attestation
explicitly tied to the full review. Its schema need not duplicate a historical
large audit schema. No placeholder or historical receipt can satisfy preparation:
actual results, raw event digest, independent admission, full review, captured
protocol and current cohort build hashes must match. The protocol preparer
launches nothing and writes `protocol.json` only after all prerequisites pass:

```sh
source scripts/env.sh
python3 target/guard-performance-review/optimized-performance-proposal/fresh-uncaptured-proposal/prepare.py \
  --captured-independent-admission /absolute/path/to/fresh-captured-admission.json \
  --captured-independent-admission-sha256 ACTUAL_SHA256
```

The generated protocol remains `SOURCE_REVIEW_REQUIRED_NO_NUMERICAL_GRANT`.
It freezes both actual uncaptured binaries, their archive identities/link maps,
all build/captured/projection sources, the actual captured anchors and independent
review, Python/toolchain bindings, exact inputs and control shapes. The first
protocol/run directory is preserved; no retries or extensions are implicit.

After independent source/protocol review and a separately allocated numerical
slot, the future bounded execution command is the source-only run.py path plus
its reviewed protocol SHA. A successful stage still requires an independent
saved-data audit of all120 uncaptured events,52 exact projections, retained

process terminals, cleanup, cancellation and deadline. Preflight/quiet timing
remains a separate later gate with its own preregistration and resource grant.
