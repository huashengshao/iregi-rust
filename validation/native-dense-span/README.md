# Isolated dense active-span native batch experiment

This candidate changes only the batch loop representation in a private copy of oneloopmaster's existing RustEmitter. Production sources remain unchanged. It is separate from the native stack-allocation experiment: both variants here use the original unallocated SSA evaluator. Existing Symbolica expression construction, numerical primitives, operand order, constant tables, control labels, temporary slots and helper calls are unchanged.

At function entry and each IfElse, Goto or Label transition, a sorted unique active list is classified as one contiguous half-open span or an arbitrary subset. The sorted unique invariant follows the root 0..rows sequence, stable conditional compaction, ordered Label reconstruction and inherited helper lanes. Empty lists produce 0..0. Multi-operand Add/Mul use an integer range loop for a span and retain the original indexed loop otherwise. All operand reads complete before the destination write, including allocated aliases in the independent control fixture. Outlined blocks round-trip span state alongside active length; helpers keep the parent workspace stride. Other instructions retain their previous implementation.

`check_baseline.py` confirms that the baseline emitter output matches checked-in production native kernels after exact constant-index expansion. `check_dense_shape.py` removes only the exact span metadata and duplicate dense/sparse Add/Mul loop, expands transparent outlining wrappers, and compares every remaining ordered primitive, operand slot, constant, control label and helper call. It deliberately does not erase arena addresses. Scalar source remains byte-identical. The source shape check also covers a Symbolica-built aliased fixture.

The frozen runtime archives come from `../native-stack-batch/deps`, with hashes in each build report. Private emitter copies adapt only their module path and runtime reexport to compile outside the dependency crate. Both private baseline and candidate generator outputs are compared with the frozen public emitter. New generic kernels use rustc opt3/codegen16; the shared archived runtime is the opt2 development build. These are native-kernel experiments, not original IREGI or release end-to-end benchmarks.

The f64 corpus includes all six ordinary master outputs, 24 configurations per family, rows0/1/3/7/32 with reordered and branch-mixed inputs, scale changes, massless/scaleless cases and workspace stride reuse. Old/new outputs require equal represented values, precision and signed zeros. Existing differences against the separate Symbolica interpreter are counted independently; they do not qualify as exact cross-backend agreement. A NaN-containing lane must leave valid neighbors unchanged, match raw classification between variants and trigger the existing public NonFiniteInput diagnostic. Invalid array shape must leave signed-zero sentinels untouched.

A separate six-output control fixture is constructed entirely with Symbolica: a guarded sum of 140 rational terms, followed by unguarded uses. Its 431-instruction allocated evaluator has 141 source/destination aliases and delayed Label reactivation across outlining. Its 36 configurations explicitly exercise a nonzero-origin span3..7, alternating holes, empty/all active lists, rows0/1/3/7/8/32/33 and shrinking retained strides. Inactive inputs place a pole in the skipped branch. Each valid output is checked against the unchanged scalar emitter and both batch variants, including signed zeros. This arbitrary fixture is not a scalar-master Laurent vector.

`build_fixed.py FAMILY` builds paired f64-only binaries. `run_fixed.py FAMILY --phase before --cpus 20,21` performs qualification; `--benchmark --cpus 0` is only run in a root-coordinated quiet window, followed by `--phase after`. Timing uses 21 alternating paired blocks, a common iteration count selected by untimed pilots, one elapsed read per block, and per-call black-box input/output. Exact old/new checks run after warmup, pilots and each measured pair. No timing result is claimed before the parser and uncertainty gate pass. Higher precision and Dual qualification of this emitter change remain pending; the other allocator experiment's all-domain results cannot qualify this candidate.

Source and attributable machine text sizes are reported separately. Duplicating dense and sparse paths can increase instruction-cache cost. Static packed instructions do not prove multi-sample vectorization or runtime benefit. All paired results, including regressions and noisy measurements, must remain visible before any adoption decision.

## Measured disposition

Reject adoption. All 12 CPU 254 fixed-loop groups have sufficiently narrow intervals: six singleton parity results, two improvements and four batch32 regressions. B0 batch32 candidate/baseline ratios are 0.979072 (homogeneous), 0.996750 (interleaved) and 1.011286 (grouped). C0 batch32 ratios are 1.012983, 1.093112 and 1.103252 respectively; all three regress. `timing-fixed-summary.json` retains every sample, 99% bootstrap interval and gate. The two improvements cannot compensate for the four regressions. The independent allocator D0 experiment is in `../native-stack-batch` and is also rejected; its different candidate and historical CPU 0 results must not be merged with these measurements.

Baseline→candidate source sizes are B0 94,452→136,533 bytes and C0 2,745,551→3,504,129 bytes. Attributable named machine text grows B0 132,708→331,702 and C0 2,574,958→7,215,714 bytes; shared library/inlined code is excluded from these named-symbol sums. Paired f64 builds took 33.12 and 174.29 seconds respectively. These compile durations are diagnostics under ambient host load, not comparative build-performance claims. Increased code size is a plausible cost, not a measured cache-miss attribution.

For report-only replay in a fresh checkout, source `scripts/env.sh`, run `python validation/native-dense-span/restore.py`, then `python target/native-dense-span/analyze_fixed.py`. The restore tool validates every evidence hash, the shared analysis helper and all archived source hashes, and refuses an existing target directory. `generated-sources.tar.gz` contains exact private emitters, paired generated B0/C0 modules, constants, wrappers and Symbolica-built fixture/provenance. Historical runtime archives and binaries are omitted; their exact hashes and compiler arguments remain in build records. New builds require the frozen runtime archives documented in `../native-stack-batch`, or a separately recorded new dependency scope. Reproduction does not require a Symbolica license for report-only analysis. Never archive private license values.

`quiet-window` preserves the root coordinator's completed window and two CPU surveys. CPU 0 had unrelated load; these new measurements were pinned to CPU 254. Prior allocator measurements on CPU 0 remain explicitly separate. B0/C0 all 24 physical configurations and the 36 control-fixture configurations pass on the exact measured binaries before and after timing, with byte-identical parity CSVs and logs. No higher-precision or Dual claim is made for this rejected dense-loop candidate.
