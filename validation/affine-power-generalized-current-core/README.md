# Actual affine positive-power reduction: scoped saved evidence

This capsule preserves the actual Cargo build and CLI evaluation of the new
affine positive-power reduction engine. A regular constant-one denominator
identity descends from dynamic point counts to packed child topologies while
keeping the requested tensor rank, denominator powers, dimension and numerical
component layout. This archive records the tested boundary; it does not qualify
the entire generalized interface.

At one fixed massive six-propagator, rank-six, unit-power kinematic point,
both Float128 and Float256 CLI captures return all 210 tensor moments and four
native Laurent slots. The portable checker compares all **840 complex slots per
precision** against admitted original quad IREGI using a dimensionally normalized
mixed tolerance of `1e-10`. It separately checks 420 exact IR zeros and 210 exact
power-counted UV zeros per capture. The maximum reference error is approximately
`2.10018e-16`. All **840 precision pairs** pass normalized `2^-80`; the maximum
128/256 difference is approximately `1.80270e-31`.

The outer request remains IBP, and the actual child method is explicitly
**Passarino–Veltman completion**. The recorded affine chart has four DAG edges,
four packed N5 rows in one child batch, 120 scalar-master rows over four master
families, and a parent with no scalar masters. Original child preparation notes,
lane diagnostics, route flags and precision settings remain in the raw records.
The imported quadrature/error-program row counter does not count native
quadrature-master integrations. No pure-IBP performance claim is made.

Two generalized requests remain failed: the first dotted propagator and the
D6 unit-power case each reached an 810-second child timeout at Float128 without
producing a tensor array. Their terminal receipts and logs preserve successful
owned-group cleanup. Their Float256 partners are **unrun**. Portable replay exits
successfully when this evidence is intact, while always reporting
`full_requested_generalized_corpus_qualified=false`.

The capsule also retains the initial build's three test-only Symbolica
replacement-API compile errors; the successful four-command core/CLI/public
example/PyO3 feature build; the initial listing-only test failure; its single
module-path correction; all 56 exact focused test passes; and the separate
77.24-second preparation-only guard test. PyO3 was checked with
`standalone,native`; this is not an extension import/runtime qualification.
Independent source, build, test, UNIT128 and UNIT256/pair audits are preserved.

The **145 selected source copies from build002** occur once in `sources.tar.gz`.
The earlier build's two distinct test-source bodies are retained separately;
its other source aliases reuse the same bytes. These are immutable historical
copies, independent of later live-main edits. The snapshot includes the exact
root lock/manifests, selected workspace Rust sources and the specifically patched
Symbolica source/provenance files; it is not a complete external dependency
closure or a self-contained build distribution.

Native executables and license values are omitted. Cargo-emitted artifact events,
product hashes and historical terminal guard statements are retained. Replay
explicitly checks available bytes and recorded omitted identities; it does not
claim to rehash an absent executable, rerun a supervisor, probe current process
state or establish a new no-overlap assertion. The admitted original quad
reference uses 113-bit storage while retaining the original approximately
16-digit constants and stopping criteria.

Run the portable saved-only check with Python's standard library:

```sh
python3 validation/affine-power-generalized-current-core/check.py
```

`restore_files(manifest)` returns project-relative saved byte aliases and reuses
the pinned `validation/quad-original-iregi-generalized-n6-rank6` capsule. The
manifest lists the exact 52 parent files needed for a fresh validation-only
checkout, together with every own capsule file. No compiler, network, native
library, numerical producer, model installation or existing `target` tree is
needed. `package.py --seal` is archival tooling; it requires the original saved
target records and refuses to replace an existing manifest.

No full Dual, physical numerator, rank-seven, arbitrary kinematic/domain or
performance qualification is inferred from this capsule. Captured durations
are engineering diagnostics, not benchmark measurements.
