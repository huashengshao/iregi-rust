# Uninstrumented dependent qualification — source-only proposal

No relink, reduction kernel or performance run is granted or executed by this proposal. The private uniform-branch candidate has passed its local Symbolica gate: one successful opt0 compile and exactly 15 requested tests, including genuine original-batch/candidate/scalar output and ordered active-lane trace comparisons. The two earlier test-constructor compile failures remain retained. This result does not qualify the complete TIRust pipeline or a runtime gain.

## Minimum dependency rebuild

Build two isolated variants, each with one Symbolica kernel per process. Keep all numerical source, crate features, flags, input fixtures and master policies identical. The only production source difference is the reviewed `evaluate/batch.rs` uniform-jump patch (original `eb73974b...`; candidate `6db2acb4...`). Remove all test-only trace hooks, the renamed frozen evaluator and its extra parent module declaration. Reversal must exactly reproduce the original reviewed production files before either archive is compiled.

Each variant needs five sequential rustc products: Symbolica rlib, OneLoop rlib, iregi-masters rlib, iregi-rust rlib, and a small standalone observation probe. Existing OneLoop/masters/core archives embed the old Symbolica identity; reusing them with a new candidate archive could introduce a second kernel or incompatible types. Do not do that. Every unaffected external archive and GMP/MPFR/MPC library can be reused from the complete frozen non-Python closure. No Cargo, FeynKit, preparation crate, CLI, Python, NumPy or Typst build is needed.

The exact Symbolica extern mapping and feature set are already recovered in `../qualification-plan-v4/extern-map.json` (28 direct externs). The retained OneLoop fingerprint `target/cargo-build/debug/.fingerprint/oneloop-ad2b1eccf125afee/lib-oneloop.json` records features `default,generated-evaluators,prebuilt,rust-codegen` and precisely three dependencies: the newly built Symbolica plus frozen bincode and symjit. Both latter archives are already in that exact Symbolica extern map. Preserve these features initially; do not save build time by silently changing the numerical backend.

Masters needs the newly built OneLoop and Symbolica. Core additionally needs frozen serde and the independently qualified supplemental thiserror archive/proc macro from `target/core-fused-cse-census/supplemental-deps/`. The probe additionally needs frozen serde_json. The existing native-policy qualification preparation records those exact supplemental paths/hashes. Recover their exact receipts, hash the inputs, and use explicit extern arguments rather than selecting archives with globs.

Keep the new archives in per-variant directories with distinct metadata identities. The probe and every dependent must reference the matching new archive chain explicitly. Include a linker input trace or equivalent archive-binding check to establish that only the selected new Symbolica kernel reaches each executable; the old Symbolica/OneLoop/masters archives in the search closure must never become externs for this stage.

Use the same opt0 correctness profile for both variants: pinned compiler/linker, debug assertions and overflow checks, no LTO/debuginfo, explicit codegen units, and the recovered features/build-script environment. No compatible incremental reuse is established. The successful local test compile took 117 seconds (126 seconds including guards); it does not predict archive/codegen duration or provide a numerical benchmark.

## Staged bounded grants

Before execution, freeze complete private source/data inventories, the exact per-variant command arrays, tool/extern/native hashes, all output paths and one first-failure policy. Reuse the byte-identical reviewed lifecycle helper with an aggregate cleanup reserve, owned-group checks after leader exit, terminal receipts before hashes, deferred cleanup signals and final input/output guards.

Suggested first grant: only the two uninstrumented Symbolica rlibs, sequential, each with a separate conservative 180-second compiler cap and reviewed aggregate budget. A failure or timeout terminates the grant and stays visible. Request a separate reviewed grant for the OneLoop→masters→core→probe chains once the Symbolica archives exist. Those commands and caps must be explicit before launching; do not start an unbounded aggregate build or promise that the local test build's duration applies.

The initial backend should be the same generic Symbolica master policy in both variants, so both the recurrence evaluator and generic master evaluators actually exercise the changed scheduler. Keep the separately qualified optional native master policy out of this comparison until the generic chain passes. A later compatibility cohort can select the same native policy in both variants; combining two independent candidates before qualification would obscure the cause of a difference.

## Full numerical observations

Reuse the fixed input fixtures and record schema from the completed native-policy qualification as inputs/schema only, never as substituted output values. Adapt the probe to one generic policy and execute it separately against each archive chain. Its existing `core_probe.rs` and `master_controls` preparation code expose exact represented values, precision, sign/finite metadata and full master records. Any required observation hooks must be logging-only, identical in both variants, source-reviewed, and separate from the uninstrumented production candidate. The Symbolica scheduler itself stays uninstrumented.

For every input, retain all tensor moments and four native Laurent slots, all requested Taylor components, each master's arguments/results, normalization/scale context, status/failure/fallback diagnostics, lane masks and structural operation/request counters. Require exact own repeats and exact baseline/candidate represented values plus metadata because this scheduler patch changes no active arithmetic. Do not infer success from a contraction, checksum, selected moments, tolerance-only comparison or prior reference output. Actual active instruction traces were already compared in the local scheduler gate; raw empty-dispatch counts may decrease by design and must not be confused with the unchanged mathematical operation/request counters.

Include the complete frozen core/master control inventory, empty/singleton/odd/tail/chunked/reordered batches, warm workspace reuse, mixed branch/mass choices, a failing lane beside good lanes, signed zero and complex branches. Retain f64, DoubleFloat and increasing/mixed Float precision cases with inputs separated beyond 53 bits. Preserve static/dynamic Dual shape metadata and higher/mixed derivative components; include C0/D0 as well as A0/B0. Constants and inputs must stay exact until mapped into the chosen Symbolica numeric context. Unsupported or failed cases stay in the output and their expected masks cannot be used to hide new failures.

The current native-policy harness compares two master policies in one executable. That comparison wrapper cannot be reused unchanged: this proposal compares two Symbolica crate identities in separate executables, with the same generic policy. Only its already reviewed preparation/record code and fixed fixtures are reusable. Pin each executable and its matching build receipt throughout every numerical run and exact repeat; use lifecycle-owned copies as in the existing qualification.

An independent reviewer should recompute full-record equality, verify exact inputs/source/build/run bindings and inspect every failure mask. If a pre-existing scalar-vs-batch or original-reference disagreement is encountered, retain it separately; do not weaken thresholds or relabel it as a successful scheduler result. The N6 rank7 original-reference failure remains unrelated and unchanged.

## Later performance gate

Only after the dependent numerical cohort passes should a separate matched optimized pair be built and timed in an approved quiet window. Measure singleton and batch32 per topology/rank/mass family plus scaling, one pinned core, identical caches/requested outputs, warm-up/repeats and uncertainty. Keep guards and exceptional branches intact, retain failed/noisy cases, and use TIRust/reference ratios. The opt0 build/test durations above are diagnostic lifecycle data and must never appear as kernel speedups. No live application or production adoption is justified by this proposal alone.
